# Memory Management(项目长期记忆的管理界面与 API)

## Why

长期记忆是产品叙事的核心一环("两层记忆:会话压缩 + 异步结构化整理"),
后台 consolidator 已在做增删改,检索时注入上下文。但用户对记忆唯一的
可见性是检查器里"已使用的长期记忆"只读列表——记忆里写了什么、积累了
多少、有没有错的/过时的条目,用户既看不到全貌,也改不了、删不掉。
一个会悄悄影响后续回答的隐形状态,用户却没有任何控制权,这是信任问题:
"它是不是记错了我的偏好?我不知道,也管不了。"

## What Changes

1. **记忆管理面板**:项目级页面/抽屉,列出全部长期记忆条目(类型、内容、
   更新时间、来源),按类型筛选、按关键词搜索。
2. **用户 CRUD**:手动新增条目(如研究偏好、术语约定)、编辑、删除,
   均带确认;用户操作标记 `user_managed` 来源,与系统整理条目区分。
3. **后端 API**:`GET/POST/PATCH/DELETE` 项目记忆路由,归属校验,复用
   既有 memory 仓储与 consolidator 的数据模型,不建第二份存储。
4. **检查器联动**:"已使用的长期记忆"条目可跳转到管理面板定位同一条。
5. **诚实边界**:来源信息按仓储实际记录展示(有 provenance 显示来源
   run/会话,没有显示"系统整理");不编造。

## Non-goals

- 不做跨项目共享记忆、记忆导出/导入。
- 不做 ResearchArtifact/证据级记忆(durable-research §7 方向);本变更
  只管理既有 generic 记忆条目。
- 不改 consolidator 的自动整理策略;用户编辑只防覆盖(见 design)。
- 不做记忆的 diff/版本历史。

## Impact

- Backend:memory 仓储补用户面 CRUD 与列表查询(含筛选/搜索)、
  FastAPI 路由、`user_managed` 标记与简单防覆盖(last_updated 保护)。
- Web:记忆管理面板(新)、检查器"已使用记忆"联动跳转、路由入口。
- Tests:API 权限/CRUD、防覆盖语义、面板渲染与联动。
- Docs:README 两层记忆条目更新。
